# 去 slop：一道一道做减法

已有界面看着像 AI 默认皮、要改造（restyle）时读。审查时也可以只做第 1 步普查，把结果当证据。规则本身在 [look-and-copy.md](look-and-copy.md)；这里只定**顺序和证据**：先测量，再去色，再一类一类减，最后只把有含义的颜色加回来。凭感觉"改好看"的改法，不按这里做。

方向还没定时，先按 look-and-copy.md 的"开工前"定方向。这个流程只负责把默认皮拿掉，不负责另选一套样子。

## 1. 普查：先看页面实际用了哪些值

改之前先列出实际渲染出来的值，作为改造前的证据。能在浏览器里跑就在页面控制台执行：

```js
(() => {
  const props = ['paddingTop','paddingRight','paddingBottom','paddingLeft','marginTop','marginRight','marginBottom','marginLeft','rowGap','columnGap','borderTopLeftRadius','fontSize','fontWeight','color','backgroundColor'];
  const seen = Object.fromEntries(props.map(p => [p, new Map()]));
  for (const el of document.querySelectorAll('body *')) {
    const cs = getComputedStyle(el);
    for (const p of props) {
      const v = cs[p];
      if (!v || v === '0px' || v === 'normal' || v === 'rgba(0, 0, 0, 0)') continue;
      seen[p].set(v, (seen[p].get(v) || 0) + 1);
    }
  }
  return Object.fromEntries(props.map(p => [p, [...seen[p]].sort((a, b) => b[1] - a[1])]));
})()
```

没有浏览器时读 CSS 和内联样式，把 padding、margin、gap、圆角、字号、字重、颜色的取值列出来，并注明"来自源码，未看渲染"。

普查结果里要标出：

- **不在刻度上的间距**：项目有间距刻度就用项目的；没有时用 4 的倍数，并从现有值里归纳出一组（例如 4、8、12、16、24、32、48）。17、26、37 这类值逐个列出位置。
- **圆角种类**：同一角色（按钮、卡片、输入框）有几种圆角。
- **字号和字重的种类**：有没有主次，还是全是粗体。
- **颜色**：每种颜色在做什么；说不出用途的颜色单独列出来。

把刻度和其他具体值补进族卡（[visual-family.md](visual-family.md)）。

## 2. 八道减法

每道只改一类东西，改完截一张图（没有浏览器就记下改了哪些声明）。顺序固定，因为前面几道会让后面的问题变得明显：

1. **间距归到刻度**：普查里不在刻度上的值改到最近的刻度值。只改数值，不改结构。
2. **去掉底色**：渐变底、光晕、玻璃拟态、彩色阴影换成中性的底和面板。这一步连图表、徽标、按钮一起先变灰，颜色在第 8 道再加回来。
3. **对齐**：同一列的左边缘对齐（logo、搜索框、导航项、分组标题）；同类元素的内边距一致。
4. **统一图标**：emoji 当图标的换成同一套图标，或者去掉图标；一个界面里不混用两套。表示类别的可以换成小圆点，颜色留到第 8 道定。
5. **改文案**：按 look-and-copy.md 改。后台和仪表盘的重点在那里的"产品界面"一节：欢迎语标题、感叹号、全大写小标题、品牌名里的装饰、"Search anything..."这类占位符。
6. **数字和图表说真话**：指标写比较基准和单位，用等宽数字；图表补坐标轴、刻度和单位。拿不到真实刻度或数据时记成缺口，不编。
7. **收字重和字阶**：去掉"全部加粗"，标题和正文拉开主次；次要信息用浅色而不是更小的粗体。
8. **把颜色加回来，只加给有含义的地方**：状态（成功、警告、错误）、数据系列、一条品牌强调色。同一含义在所有区域用同一颜色，例如侧栏里某个套餐的圆点和图表里这个套餐的系列是同一颜色。说不出含义的颜色不加回来。

不是每道都有活：某道没有可改的，写"本道无改动"和理由。

## 3. 不要做

- 不要把"改造后"的样子当成新的默认皮。深色、细线图表、等宽字体是某个产品的选择，不是去 slop 的答案。方向仍然来自内容和读者。
- 不要改功能和数据：元素、id、链接、事件处理保留；页面上的数字一个不改，不补新指标。
- 不要一次全改再截一张最终图。每道单独留证据，出问题时才知道是哪一道造成的。
- 不要用模型自评当"已经不像 AI"的证明。证据是普查前后的对比和每道的截图。

## 4. 完成条件与交付

- 普查里不在刻度上的间距清零（或者每个保留值都写了理由）。
- 每种颜色都能说出含义；同一含义跨区域同色。
- 数字没变；功能元素和事件都在。
- 报告列出：改造前的普查摘要、刻度、八道各改了什么（或为什么没改）、仍然是缺口的地方（例如图表没有真实刻度）、哪些需要在浏览器或真机上确认。
