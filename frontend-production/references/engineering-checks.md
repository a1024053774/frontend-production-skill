# 工程检查：逐实例查什么

审到某个页面或组件时读对应小节，不必一次读完。流程、分母和台账见 [review-workflow.md](review-workflow.md)。每一项都是要回答的问题，不是要求每个组件都实现的功能：纯静态组件不硬套异步检查，项目没有暗色模式就不要求暗色模式。

## 1. 八个维度

每个实例逐维给出状态和证据或理由：

| 维度 | 要回答 |
|---|---|
| 行为 | 每个操作的正向、反向、取消、中断、重复是否都对？有没有假按钮、假链接、点了没反应的控件？ |
| 状态 | 加载、空、错误、部分成功、禁用、只读、选中这些状态是否都存在且互不矛盾？ |
| 语义与可访问性 | 原生元素、名称、角色、状态、键盘、焦点、读屏播报（第 4 节） |
| 布局与内容 | 长文本、多语言、缩放、窄容器、层级和滚动（第 5 节）；样子与同族问题交给对应镜头 |
| 数据与副作用 | 数据从哪来、谁是权威、失败怎么办、会不会重复写（第 3 节） |
| 安全隐私 | 渲染了什么不可信内容、存了什么、发了什么（第 7 节） |
| 性能与生命周期 | 实测是否慢、卸载是否清理、长时间使用是否泄漏（第 6 节）；动效性能交给动效镜头 |
| 结构与集成 | 状态放对了层吗、有没有重复逻辑、与调用方的约定是否清楚、错误是否被吞掉 |

每个控件都要能被找到、认出来、操作、看懂结果、退出或恢复。只点一次成功路径不算检查过。

## 2. 组件类型要点

遇到列表外的组件，按它的职责补检查。

- **按钮和图标按钮**：真按钮还是 `div`；图标按钮有可读名称；提交中防重复；危险操作有确认或撤销；禁用时说明原因或可被读到。
- **链接和可点区域**：导航用链接、动作用按钮；整卡可点时内部控件不被吞；新窗口打开有提示；外链安全属性（第 7 节）。
- **输入框和多行文本**：可见标签而不是只有占位符；错误信息关联到字段并可被读到；中文输入法组合中不误触发提交或校验；粘贴大段、长度上限按字符还是字节说清；自动填充可用。手机端输入设置见手机端镜头。
- **复选框、单选、开关**：点击区域、键盘操作、状态播报；开关是否立即生效、失败是否回滚。
- **选择器和组合框**：键盘上下、输入过滤、无结果状态、选项很多时的性能、在弹层里被裁切。
- **日期时间**：时区、格式、手动输入、键盘可用、最小最大值。
- **表单提交和分步向导**：重复提交、超时结果未知、服务端错误映射到字段、离开时草稿是否丢、后退是否回到上一步而不是离开向导。
- **模态框、抽屉**：打开时焦点进入、Tab 被困在里面、Esc 关闭、关闭后焦点回到触发器（触发器已被删除时回到合理位置）、背景不能滚不能点、嵌套时的层级。
- **弹层、菜单、提示**：键盘可打开可关闭、不被父容器裁切、提示内容不能只靠 hover 获取（触屏和键盘也能看到）。
- **通知、横幅、错误摘要**：播报级别合适、不自动消失得太快、错误摘要能跳到对应字段。
- **标签页、分段视图**：方向键切换、当前项状态、内容是否随 URL 保存。
- **导航、侧栏、面包屑**：当前页标识、窄屏收起后能打开、深链接进入时高亮正确。
- **列表、卡片、表格**：空、1 条、很多条；排序筛选与 URL 同步；行内操作作用于正确的行；选中与批量操作；表格在窄屏的策略。
- **搜索、筛选、分页、无限滚动**：输入防抖与乱序返回、无结果状态、筛选条件可见可清除、分页后返回保持位置、无限滚动有终点和读屏可用的替代。
- **拖拽排序、分栏调整**：有键盘替代、拖拽中取消、落点提示、失败回滚。
- **上传与附件**：类型和大小校验（前端提示，后端为准）、进度、取消、重试、部分失败、重复文件。
- **富文本和代码编辑器**：粘贴清洗、撤销重做、输入法、内容保存时机。
- **图表**：有可读的数据替代、不只靠颜色、空值负值极值、窄容器。
- **图片、视频、轮播**：alt、尺寸预留防跳动、自动播放可暂停、轮播键盘可用。
- **加载、空白、错误占位**：区分"加载中""真的没有""出错了"；错误有重试；骨架屏不比真实内容跳得更厉害。
- **AI 流式消息和工具结果**：流中断和重试、停止生成、不在每个 token 抢焦点或强制滚到底、读屏播报频率、模型输出当不可信内容渲染、展示的用量和耗时说清来源。
- **长任务进度**：能取消、离开再回来能看到状态、失败可重试、不假装进度。
- **文件预览、下载、导出**：大文件、失败、权限、文件名编码。

## 3. 状态与数据

- **权威来源**：每份数据谁说了算（服务端、URL、本地状态、缓存）？同一份数据有没有两个来源互相打架？
- **URL 与历史**：筛选、分页、标签页、打开的详情是否在 URL 里；刷新、分享、后退前进后状态是否一致；登录后能否回到原页面。
- **组件身份**：列表 key 是否稳定；切换路由或对象时旧状态有没有残留在新对象上。
- **表单与草稿**：初始值何时载入、编辑中数据被后台刷新覆盖、离开提示、提交后状态重置。
- **读取与错误**：失败可重试、部分失败、空和错误分开、错误信息对用户有用。
- **竞态**：快速切换时旧请求后返回是否覆盖新结果；卸载后回调是否还在改状态；定时器和订阅是否清理。
- **写入**：重复提交、超时但服务端可能已成功、乐观更新失败的回滚、并发编辑冲突。
- **缓存与切换身份**：退出登录或切换租户后，缓存、内存状态、离线存储里有没有上一个人的数据。
- **会话与权限变化**：会话过期时进行中的写操作怎么办；权限被收回后界面是否及时更新。
- **后台作业与取消**：取消是否真的停止了服务端工作，还是只是前端不再显示。

## 4. 可访问性

- 能用原生元素就用原生元素；自定义控件补齐角色、名称、状态和键盘。
- `aria-expanded`、`aria-selected`、`aria-checked`、`aria-current` 等跟随真实状态，不是写死的模板值。
- 焦点始终可见；Tab 顺序与视觉顺序一致；没有键盘陷阱（模态框内部除外）；跳到主内容的入口。
- 成功、错误、结果数量和后台更新有合适的播报，不把整页或每个 token 放进高优先级播报区。
- 信息不只靠颜色、hover 或动画传达。文字对比满足项目目标（未定时按 WCAG AA 检查）。
- 页面放大到 200%、系统字号调大时内容不被裁掉、不需要横向滚动阅读正文。
- 尊重减弱动效和其他系统偏好；闪烁风险按官方准则核查，不凭主观舒适感判通过（动效细节见动效镜头）。

## 5. 布局与内容压力

- 长标题、长中文无空格字符串、超长数字、多语言、缺字段时是否撑破或被截断得没法用；截断后能否看到全文。
- 窄容器、窄屏、横屏、缩放下主行动是否仍然明确可点。
- 层级和定位：固定元素是否遮住内容或输入框；弹层是否被 `overflow` 裁切；`z-index` 是否互相打架；滚动锁是否释放。
- 主题和状态组合：hover、focus-visible、active、selected、disabled 各有作用，焦点不被当成选中；只在项目实际支持时检查暗色和高对比模式。
- 样式来自 token、共享定义、页面覆盖还是内联？在最小的正确层级修，不用局部硬编码颜色破坏主题。

## 6. 性能

- 先定指标和条件：生产构建、目标设备、网络、数据规模、具体操作。没有实测就写"待测"。
- 首屏：关键资源、图片尺寸和懒加载、字体加载造成的跳动、布局偏移。
- 交互：输入延迟、长任务、一次操作触发的请求数和重渲染范围（测出来再判）。
- 列表规模：真实上限下是否卡顿；只有实测证明需要时才建议虚拟列表。
- 生命周期：长时间停留后的内存、未清理的监听和定时器、反复打开关闭弹层是否泄漏。
- 包体：只在影响了实测指标时才作为问题，否则是维护建议。

## 7. 安全与隐私边界

前端只能看到一半。写清楚哪些是前端能确认的，哪些需要后端或平台证据。

- **授权**：隐藏按钮不等于没有权限。改 URL 里的 ID、直接调接口能否拿到别人的数据，需要后端证据；前端看不到时写"待验证"并按后果排优先级。
- **不可信内容渲染**：用户输入、接口数据、Markdown、富文本、模型输出是否经过转义或清洗再进 DOM；`innerHTML`、`dangerouslySetInnerHTML`、`v-html` 的来源。
- **外链与跳转**：`target="_blank"` 的 `rel`；登录后跳转地址是否可被控制成外站。
- **iframe 与 postMessage**：是否校验来源；嵌入第三方的权限。
- **存储与会话**：令牌和敏感数据存在哪；退出登录是否清理；不把私密凭据放进前端代码或公开环境变量（公开的前端 key 本身不是问题，看它的权限范围）。
- **CSRF 与 CORS**：按实际架构核对，不因"没看到 CSRF token"就判有漏洞，也不因"用了 JWT/SameSite"就判安全。
- **上传下载**：前端校验只是提示；下载文件名和内容类型。
- **日志、埋点、录屏**：是否采集了密码、令牌、个人信息；录屏是否遮罩敏感字段。
- **依赖与构建**：锁文件、已知漏洞、开发用的调试开关和 source map 是否进了生产。

## 8. 交付与可观测

- 能否从干净环境按文档构建出来；构建和测试命令是否真的在 CI 里跑；测试检查的是行为还是只是能渲染。
- 错误边界是否存在、是否上报、上报内容是否脱敏；监控挂了会不会拖垮主业务。
- 缓存和 Service Worker：发布新版本后旧页面如何更新，新旧接口共存时是否兼容。
- 发布与回滚：静态资源和接口的发布顺序、回滚后旧前端能否继续工作。
