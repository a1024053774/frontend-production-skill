# 精工减速机询价页：快审报告

审查对象：`project/index.html`、`project/style.css`、`project/app.js`（共 3 个文件，约 5 KB）
审查方式：只读源码做静态审查，没有在浏览器或真机上运行，也没有改代码。
状态：**INCOMPLETE**。下面的结论都来自读代码，运行时表现（特别是第 1 条弹窗遮挡）要在真机上复现确认。

背景前提：读者是采购，主行动是"提交询价"，主要在手机上用。已知事实只有"速比 5–100、额定扭矩至 18 kN·m"；没有任何认证、客户数、成功率的资料。

---

## 一、结论先说

这个页面现在**不能上线**。最严重的问题有三个：

1. 打开页面时，"询价已提交"弹窗很可能直接盖住整页，采购什么都点不了。
2. 询价请求只发了数量，没有手机号和型号，销售收到也联系不上人；而手机号和 token 被发给了第三方统计域名。
3. 首屏的"已获行业领先认证""99.9% 交付成功率""5000+ 企业客户"都没有资料支撑，属于虚构宣称。

## 三、修复顺序

按"先让主行动跑通且安全，再让手机上好用，最后修内容和视觉"的顺序来，每一步都可以单独验收：

1. **让弹窗不再挡住页面**（#1）：在 CSS 里加 `.modal[hidden]{display:none}`，或者改用 `<dialog>`。修完这一步才能测后面的问题。
2. **补全询价数据链路，并且只发给自家后台**（#2、#3、#4、#6、#14、#28）：把表单改成真正的 `<form>`；请求体包含型号、数量、手机号（以及第 6 步要加的需求字段）；设置 `Content-Type`；检查 `res.ok`，失败时给出明确提示并保留已填内容；请求过程中禁用按钮。统计事件里去掉手机号和 token；URL 里的 token 不写进 `localStorage`（如果确实需要 token，要先弄清楚它的用途，这一点需要产品方确认）。
3. **消除 XSS**（#5）：`note` 和搜索结果改用 `textContent` 或者逐个创建 DOM 节点。
4. **删掉虚构宣称**（#7）：删除认证、99.9%、5000+ 这些说法。拿到真实资料前，什么都不写，也不要用别的数字代替。
5. **手机表单可用性**（#8–#13、#16、#17、#19）：用真正的 `<button type="submit">`；每个输入框加 `<label>`；加 `type`、`inputmode`、`autocomplete`；输入框字号改为 16px；去掉 `user-scalable=no`；校验手机号格式和数量范围，并显示文字错误提示；底部栏处理安全区，内容区留出底部空白；去掉 `.app` 那层 100vh 滚动容器，让页面正常滚动；补上弹窗的无障碍属性和焦点管理。
6. **内容重排**（#20–#23）：首屏直接写清楚"精工减速机，速比 5–100，额定扭矩至 18 kN·m"，主按钮写"提交询价"并跳到表单；表单加需求速比和需求扭矩两栏，按已知范围校验。
7. **修正动效和交互细节**（#15、#18、#24、#25、#26）：搜索加防抖，并让结果可以选中、选中的型号写进表单；`.reveal` 去掉，或者只在 `prefers-reduced-motion: no-preference` 时启用，并且不要作用在表单上；菜单改成 `ease-out`、约 150–200ms，菜单项改成链接，补上 `aria-expanded`；hover 效果放进 `@media (hover:hover)`；删掉命令面板。
8. **统一视觉**（#27、#29、#30）：页脚改用主体的配色、圆角和字体；`submitOrder` 改名为 `submitInquiry`；确认 `/about` 是否存在。

## 四、验收方法

总原则：用真机（iPhone Safari 和一台安卓 Chrome）跑一遍完整的端到端流程，同时用 DevTools 记录网络请求。每次验收都保存截图或 HAR 文件，并记下复现步骤。

### 端到端主场景（中等难度，覆盖多数 P0 和 P1）

在 iPhone 上用 4G 网络，或者用 DevTools 模拟 Slow 3G：

1. 打开页面，URL 带上 `?token=abc&note=<img src=x onerror=alert(1)>`。
   - 通过标准：没有弹窗遮挡；没有执行 alert；`note` 原样显示为文字；`localStorage` 里没有 `authToken`。
2. 首屏不滚动就能看到速比和扭矩参数；页面上找不到"认证""99.9%""5000+"。
3. 搜索型号并选中一项，数量填 `0`，手机号填 `123`，然后提交。
   - 通过标准：表单被拦下，两个字段旁边都有文字错误提示；没有发出任何请求。
4. 改成合法值后快速连点提交按钮 3 次。
   - 通过标准：只发出 1 个 `POST /api/inquiries`；请求体里有型号、数量、手机号；带 `Content-Type: application/json`；整个过程中没有任何请求发往 `analytics.example.com` 时带上手机号或 token。
5. 用 DevTools 把 `/api/inquiries` 改成返回 500，或者断网后再提交。
   - 通过标准：显示失败提示，已填内容还在，没有出现"询价已提交"。
6. 恢复网络再提交。
   - 通过标准：出现成功弹窗，焦点移到弹窗里，按"好的"可以关闭。

### 逐项检查

| 检查项 | 方法 | 通过标准 |
