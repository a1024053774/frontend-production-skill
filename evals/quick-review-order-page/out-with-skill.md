> 模式：**快审（quick）**。这是部分审查，不代表全站覆盖，也不能作为上线结论。本次没有修改任何代码。

## 2. 结论（先看这里）

从源码推理，**这个页面目前不能完成主任务**。最严重的几条：

1. **成功弹窗一打开页面就盖住全屏，而且关不掉**（CSS 让 `hidden` 属性失效）。只要推理成立，所有用户都会被挡住。
2. **询价请求只发了数量**：手机号和型号都没有发给后端，销售拿到的询价没法回复。
3. **不管成功还是失败都显示"询价已提交"**，失败了用户也不知道。
4. **URL 参数 `note` 直接写进 `innerHTML`**，任何人构造一条链接就能在页面上执行脚本；手机号还被发给第三方埋点。
5. 首屏写着"已获行业领先认证""99.9% 交付成功率""5000+ 企业客户"，**没有任何资料能支撑**。
6. 提交按钮是 `<div>`，键盘和读屏都用不了；输入框没有标签；手机端禁止了缩放。

这几项修好之前，不建议拿这个页面去收真实询价。

## 3. 问题清单

级别按实际后果定：P0 重大／大范围失效，P1 核心任务失败或关键人群被挡住，P2 非核心或可恢复，P3 细节。"证据类型"中，**源码确证**表示静态控制流就能证明；**源码推理**表示根据浏览器规范推出来，但还没有运行复现。

### P0

#### F-01 成功弹窗在页面加载时就显示，并且关不掉

- **位置**：`style.css:16` `.modal { position:fixed; inset:0; ...; display:grid; ... }`；`index.html:43` `<div class="modal" id="modal" hidden>`；`app.js:35-37`
- **证据类型**：源码推理（CSS 层叠规则），未运行复现。
- **推理**：`hidden` 属性的隐藏效果来自浏览器默认样式 `[hidden]{display:none}`，作者样式表里的 `.modal{display:grid}` 优先级更高，会把它覆盖。所以弹窗从页面加载开始就显示：半透明黑色遮罩铺满全屏（`inset:0`），而且它在 DOM 里排在底部栏后面，会叠在所有内容上面。点"好的"只会再设一次 `hidden = true`，弹窗还是显示。
- **实际**：用户打开页面就看到"询价已提交"，遮罩挡住所有点击，没有办法关掉。
- **预期**：加载时不显示；提交成功后才显示；点"好的"后关闭。
- **影响**：所有用户、所有设备都完成不了任何操作。
- **置信度**：高（推理依据是标准层叠规则），但要在浏览器里复现一次来确认。
- **修复方向**：给 `.modal[hidden]{display:none}`，或者只在打开状态上设 `display:grid`。更好的做法是改用原生 `<dialog>` 和 `showModal()`，同时解决 F-09 的焦点问题。
- **复验**：在手机浏览器里打开页面，确认看不到遮罩，规格和表单能点；提交成功后弹窗出现；点"好的"后弹窗消失，页面可以继续操作。

#### F-02 询价请求只有数量，没有手机号和型号

- **位置**：`app.js:31` `body: JSON.stringify({ qty: ... })`；`app.js:18`（搜索结果是没有点击处理的 `<li>`，不能选）
- **证据类型**：源码确证（前端没有发送这两个字段）；业务后果待后端确认。
- **实际**：POST `/api/inquiries` 的请求体只有 `qty`。手机号只发给了埋点（F-04），没有发给询价接口。搜索结果不能点选，页面上也没有任何地方记录用户选了哪个型号。请求还没有设置 `Content-Type: application/json`，后端可能会把请求体当作纯文本，解析不了。
- **预期**：请求里至少有型号、数量和联系方式，并且后端能解析。具体要哪些字段由后端约定决定，这里不替业务发明规则。
- **影响**：就算询价成功入库，销售也不知道该联系谁、问的是哪个型号，每一条询价都等于丢了。这是大范围的核心能力失效，所以排 P0；如果后端能通过别的途径拿到联系方式（目前看不到这样的途径），就降为 P1。
- **修复方向**：让搜索结果可以选择（用原生 `<select>`/`<datalist>`，或者带键盘支持的组合框），把选中的型号存进表单；请求体带上型号、数量、手机号，并加上 `Content-Type`；字段名和后端核对。
- **复验**：在可控的测试后端或接口模拟下提交一次，抓包确认请求体有这三个字段，后端返回成功并且能查到完整记录。不要在生产环境上测。

### P1

#### F-03 失败也显示"询价已提交"，网络出错时没有任何反馈

- **位置**：`app.js:28-33`
- **证据类型**：源码确证。
- **实际**：`fetch` 遇到 4xx 或 5xx 不会抛错，代码也没有检查 `res.ok`，所以服务端报错也会弹出"询价已提交"。断网时 `await fetch` 抛出的错误没人处理，页面什么都不显示。没有提交中状态，也没有防止重复提交，连点会发出多条询价。超时这种"结果不确定"的情况也没有处理。
- **预期**：提交中按钮禁用，并显示"提交中…"；只有后端明确返回成功才显示成功；失败时说明怎么办（例如"没提交成功，请检查网络后重试"），并且保留已填的内容；结果不确定时提示用户不要重复提交，或者用幂等键防止重复。
- **影响**：采购以为已经询价，其实没有，商机就丢了；连点会产生重复询价。
- **复验**：用接口模拟分别返回 500、断网、延迟 10 秒，确认每种情况的提示都正确；提交中连点 5 次，确认只发出 1 个请求。

#### F-04 通过 URL 注入脚本（DOM XSS），手机号和 token 发给第三方

- **位置**：`app.js:13` `note.innerHTML = URLSearchParams.get('note')`；`app.js:1-2`、`app.js:4-6`、`app.js:30`
- **证据类型**：源码确证（数据从 URL 参数直接流进 `innerHTML`，中间没有任何清洗）。
- **实际**：
  - 打开 `?note=<img src=x onerror=...>` 这样的链接，就能在页面上执行任意脚本，读到 `localStorage.authToken` 和用户输入的手机号。
  - `token` 从 URL 读出来后写进 `localStorage`（第 1-2 行）。没带参数时会用 `'demo'` 覆盖原来的值，所以每次普通访问都会把已有的 token 冲掉。token 放在 URL 里，还会出现在浏览历史、服务器日志和 Referer 里；别人也可以用一条链接给受害者塞进自己的 token。
  - `track('submit', { qty, phone })` 把**手机号**连同 token 一起用 `sendBeacon` 发到 `https://analytics.example.com/e`，这是第三方域名，而且是个占位域名。
- **预期**：`note` 用 `textContent` 渲染，不允许 HTML（如果业务确实需要"加急"这种标记，就用固定的枚举值）；不从 URL 接收凭据，也不把凭据存进 `localStorage`；埋点不采集手机号和 token，上报地址换成真实的、经过确认的地址。
- **影响**：任何人都能做一条钓鱼链接；个人信息在没有告知的情况下流到第三方，有合规风险。级别：定为 P1（已确证）。如果 `authToken` 是真实的会话凭据，就升为 P0。token 能做什么要找后端确认。
- **复验**：打开 `?note=<img src=x onerror=alert(1)>`，确认页面只显示字面文字，不弹窗；提交后抓包，确认埋点请求里没有手机号和 token；确认 `localStorage` 里没有凭据。

#### F-05 首屏的认证、成功率、客户数是编造的，文案是套话

- **位置**：`index.html:18-22`
- **证据类型**：源码确证，并对照用户给出的资料。
- **实际**："已获行业领先认证"、"99.9% 交付成功率"、"5000+ 企业客户"在已知资料里都没有。"赋能智造，引领工业传动新纪元""全面、无缝、领先的一站式"是换任何一家公司名都成立的套话。英文全大写眉题"WELCOME TO THE FUTURE"和"Get Started"属于 AI 默认皮。真正有用的事实（速比 5–100、扭矩至 18 kN·m）反而被挤到了第二屏。
- **预期**：删掉这三条没有依据的说法，**不拿别的数字顶替**，记成内容缺口，等有资料再补。首屏直接给采购看事实，例如标题写"斜齿轮 / 行星减速机询价"，说明写"速比 5–100，额定扭矩至 18 kN·m"。
- **影响**：B2B 采购会核实资质，编造的认证和数字会损害信任，还可能违反广告法（"领先"等绝对化用语、没有出处的数据）。
- **修复方向**：本报告不替你写最终文案，品牌方要确认产品线和措辞。
- **复验**：逐句对照已知资料表，页面上每一个数字和资质都能找到出处；全文搜索"领先、赋能、无缝、99.9、5000、认证"，结果为 0，除非补了资料。

#### F-06 提交按钮是 `div`，键盘和读屏用不了；表单没有 `<form>`

- **位置**：`index.html:40` `<div class="btn primary" id="submit" onclick="submitOrder()">`；`index.html:30-37`
- **证据类型**：源码确证。
- **实际**：这个 `div` 不能用 Tab 聚焦，没有按钮角色，读屏不会把它读成按钮；在输入框里按回车也不会提交（因为没有 `<form>`）。手机键盘右下角的"前往/发送"也不起作用。
- **预期**：用 `<form>` 包住输入框，提交按钮用 `<button type="submit">`，提交逻辑写在 `submit` 事件里（同时避开中文输入法组合输入中途误提交）。
- **影响**：只用键盘的用户和读屏用户完成不了主任务。
- **复验**：只用键盘，Tab 能到达"提交询价"，按 Enter 或空格能提交；VoiceOver/TalkBack 读成"提交询价，按钮"；在手机号输入框里按键盘的"发送"键能触发提交。

#### F-07 输入框只有占位符；校验只靠红框，手机号不校验

- **位置**：`index.html:32-35`；`app.js:21-26`；`style.css:9-10`
- **证据类型**：源码确证。
- **实际**：
  - 输入框没有 `<label>`，开始输入后占位符消失，字段名也就看不到了；读屏只能读出占位符，或者什么都读不出来。
  - 数量校验失败时，唯一的提示是边框变成 `#d00`：没有文字、没有 `aria-invalid`、没有关联的错误说明，只靠颜色传达。用户点了提交没反应，也不知道原因。
  - 正则 `^\d+$` 会放过 `0` 和 `007`；手机号完全不校验，空着也能提交。
  - 手机号没有 `type="tel"` 和 `autocomplete="tel"`，数量没有 `inputmode="numeric"`，手机上弹出的是全键盘，也不能自动填充。
  - 输入框边框 `#d9d2c7` 对白色背景的对比度只有约 1.5:1，低于非文字元素要求的 3:1，在手机上看不清输入框的边界。
- **预期**：每个字段都有可见标签；错误用文字显示在字段旁边，并用 `aria-describedby` 关联、能被读屏读出；提交失败时焦点跳到第一个错误字段；数量必须是正整数；手机号是否必填、格式怎么校验要业务确认（前端只做提示，以后端为准）。
- **复验**：空表单提交，每个必填字段旁边出现文字错误，读屏能读出来，焦点在第一个错误字段上；在 iOS 和 Android 真机上，点手机号弹出数字拨号键盘，点数量弹出数字键盘，能自动填充手机号。

#### F-08 手机端禁止缩放，输入框字号会触发 iOS 自动放大

- **位置**：`index.html:5` `maximum-scale=1, user-scalable=no`；`style.css:9` `input { font-size:14px }`
- **证据类型**：源码确证；放大效果需要真机确认。
- **实际**：禁止缩放是可访问性失败，视力不好的采购看规格时没法放大。禁止缩放的真正原因是 14px 的输入框会让 iOS Safari 在聚焦时自动放大页面；`maximum-scale=1` 只是掩盖了这个问题，修错了地方。
- **预期**：viewport 改成 `width=device-width, initial-scale=1, viewport-fit=cover`，去掉 `maximum-scale` 和 `user-scalable`；输入框字号至少 16px。
- **复验**：在 iPhone Safari 真机上双指能放大；点输入框时页面不会自动放大；Android Chrome 上同样检查一次。

### P2

#### F-09 弹窗没有焦点管理和对话框语义

- **位置**：`index.html:43-45`；`app.js:32`、`app.js:35-37`
- **证据类型**：源码确证。
- **实际**：没有 `role="dialog"`、`aria-modal`、标题关联；打开时焦点不会移进弹窗，Tab 键不会被限制在弹窗里，按 Esc 不能关闭，关闭后焦点也不会回到触发它的按钮；背景还能滚动。
- **预期**：用原生 `<dialog>` 加 `showModal()`，它自带上面这些行为的大部分；关闭后焦点回到提交按钮。成功提示也可以不用弹窗，改成在页面里显示结果，并用 `role="status"` 播报。
- **复验**：用键盘提交后，焦点在"好的"上，Esc 能关闭，关闭后焦点回到提交按钮；读屏会读出"询价已提交"。

#### F-10 型号搜索：结果不能选，旧请求可能覆盖新结果，接口数据直接进 `innerHTML`

- **位置**：`app.js:15-19`
- **证据类型**：源码确证（竞态和注入要运行或看后端数据才能复现）。
- **实际**：每输入一个字符就发一次请求（中文输入法组合输入时也会发），没有防抖；慢请求后返回会覆盖新结果；没有加载中、无结果、出错三种状态；`res.json()` 遇到错误页会抛错，没人处理；`m.name` 不经转义就拼进 `innerHTML`，如果型号名里能写入 HTML，就是第二个注入点。结果不能点选，这一点已经并入 F-02。
- **预期**：输入防抖，并且组合输入结束后才搜索；用 `AbortController` 取消旧请求，或者丢弃过期响应；分别显示"搜索中""没有找到该型号""搜索失败，请重试"；用 `textContent` 或创建元素来渲染；能用键盘选择结果。
- **复验**：用接口模拟让第一个请求延迟 2 秒，快速输入两次，确认最后显示的是第二次的结果；模拟返回 `[]` 和 500，确认分别显示对应状态；用 `{"name":"<img src=x onerror=alert(1)>"}` 测试，确认只显示文字。

#### F-11 页脚是另一套皮（同族否决）

- **位置**：`style.css:17-18`；`index.html:49-51`
- **证据类型**：源码确证（比对 token 值）。
- **从现有代码抄出的族卡**：底 `#f6f3ee` · 字 `#1d1b18` · 强调 `#b23a1e` · 边线 `#d9d2c7` · 字体 `"Noto Sans SC", system-ui, sans-serif` · 圆角 `6px`（`--radius`）。
- **实际**：页脚用的是 `"Playfair Display", Georgia, serif`、深紫底 `#1a1033`、紫色链接 `#8b5cf6`、`24px` 圆角，这四项全都不在族卡里，属于"没改皮就嵌进来的带皮 Footer"，也是"紫色叠近黑底"的默认皮。Playfair Display 没有加载，中文会回退到系统衬线字体。链接 `#8b5cf6` 对底色 `#1a1033` 的对比度约 4.25:1，低于 AA 要求的 4.5:1。
- **预期**：页脚改用族卡里的 token（例如底用 `--ink`、字用 `--bg`、链接用可读的浅色强调或下划线）、项目字体栈和 `--radius`，结构保留不变。
- **复验**：在计算后的样式里，页脚的 `font-family`、`background`、`color`、`border-radius` 都来自族卡 token；链接对比度 ≥ 4.5:1。

#### F-12 底部固定栏、`100vh` 滚动容器和安全区

- **位置**：`style.css:3` `.app { height:100vh; overflow-y:auto; }`；`style.css:11` `.bottom-bar { position:fixed; bottom:0; ... }`
- **证据类型**：源码推理；需要真机确认。
- **实际**：手机上 `100vh` 是地址栏收起时的最大高度，加上内部滚动容器，地址栏不会随滚动收起，页面底部会被压在可见区域外面；`.app` 没有给底部栏留出空间，页面最后的内容（手机号输入框、页脚）会被固定底部栏挡住。底部栏没有处理安全区，在全面屏 iPhone 上可能贴到 Home 指示条。软键盘弹出时，手机号输入框和底部栏的位置关系也没法从代码判断。
- **预期**：去掉内部滚动容器，让文档自然滚动（或者改用 `100dvh`）；页面底部留出等于底部栏高度的内边距；底部栏加 `padding-bottom: calc(12px + env(safe-area-inset-bottom, 0px))`，并配合 `viewport-fit=cover`（见 F-08）。
- **复验**：iPhone 和 Android 真机各测一次：能滚到页脚并看到全部内容；手机号输入框聚焦时不被键盘或底部栏挡住；底部按钮不压在 Home 指示条上。

#### F-13 假控件："Get Started"、产品菜单、命令面板

- **位置**：`index.html:22`、`index.html:13-14`、`index.html:47`；`app.js:8-10`、`app.js:39-44`；`style.css:7-8`、`style.css:14-15`
- **证据类型**：源码确证。
- **实际**：
  - "Get Started"没有任何处理函数，点了没反应，还跟底部的"提交询价"抢主行动（一屏应该只有一个主行动）。
  - 产品菜单里的 `<li>` 不是链接，点了去不了任何地方；按钮没有 `aria-expanded`；菜单收起时只是 `scale(0)` 加 `opacity:0`，读屏仍然会读到它。
  - Cmd/Ctrl+K 命令面板在一个手机询价页上没有用途，里面的输入框也没有任何功能。它隐藏时用的是 `opacity:0` 加 `pointer-events:none`，还能用 Tab 聚焦到，键盘用户会进入一个看不见的输入框。
- **预期**：删掉"Get Started"，或者改成"填写询价"并跳到表单；菜单项要么做成真实链接，要么连菜单一起删掉（取决于有没有产品页，需要你确认）；删掉命令面板。
- **复验**：页面上每个可以点的东西点了都有结果；从页面顶部按 Tab 一路走下去，不会经过看不见的元素。

### P3

#### F-14 动效：每块都上浮进场、菜单用 `ease-in` 和 `scale(0)`、hover 没有门控

| 之前 | 之后 | 原因 |
|---|---|---|
| `style.css:12` 三个区块都用 `.reveal`：`opacity:0; translateY(40px); 900ms ease` | 删掉，或者只给首屏留一次轻微进场：`opacity` 加 `translateY(8px)`，`300ms`，`cubic-bezier(0.23, 1, 0.32, 1)` | 每块都 fade-up 是否决项；900ms 超过 300ms 的预算；规格和表单在这段时间里看不见 |
| 没有 `prefers-reduced-motion` | `@media (prefers-reduced-motion: reduce)` 下去掉位移，只保留透明度 | 减弱动效是更少、更轻，不是归零 |
| `style.css:7` `.menu { transition: all 400ms ease-in; transform: scale(0); transform-origin: center }` | `transition: transform 200ms var(--ease-out), opacity 200ms var(--ease-out)`；从 `scale(0.95)` 加 `opacity:0` 开始；`transform-origin` 放在触发按钮一侧 | `all`、`ease-in`、`scale(0)` 都是一眼就拦的问题；下拉菜单要从触发器展开 |
| `style.css:14-15` 命令面板 300ms 过渡 | 不加动画（如果面板留下的话） | 键盘触发的动作不加动画 |
| `style.css:5` `.btn:hover { transform: scale(1.05) }` 没有门控，也没有过渡 | 放进 `@media (hover: hover) and (pointer: fine)`；另外给 `:active` 加 `scale(0.97)`、`160ms ease-out` 的按下反馈 | 触屏上点一下 hover 会粘住，提交按钮会一直是放大的状态；手机上需要按下反馈 |

- **证据类型**：源码确证；手感要真机确认。
- 菜单那一行按动效审计的 HIGH 来算是 P2，但菜单本身可能整体删除（F-13），所以这里统一记成 P3。

## 5. 验收方法

每条问题下面都写了具体的复验步骤。整体验收用下面这个端到端场景，要在**真机**上跑（iPhone Safari 和 Android Chrome 各一台，最好有一台旧手机），后端用可控的测试环境或接口模拟，不碰生产：

1. 打开 `?note=<img src=x onerror=alert(1)>`：页面没有遮罩，没有弹窗，`note` 只显示成文字。
2. 双指放大规格表，能放大。
3. 搜索一个型号：模拟慢请求和乱序返回，最后显示的是最新结果；选中一个型号。
4. 数量填 `0`，手机号空着，点提交：每个字段旁边出现文字错误，读屏能读出来，焦点在第一个错误字段上。
5. 填好合法的数量和手机号，模拟后端返回 500：提示失败，已填内容还在，没有显示"已提交"。
6. 恢复后端，提交中连点 3 次：只发出 1 个请求；请求体有型号、数量、手机号；埋点里没有手机号和 token。
7. 显示成功；关闭后能继续操作页面，焦点回到提交按钮。
8. 只用键盘、开着 VoiceOver 再走一遍第 3-7 步。
9. 打开系统的"减弱动态效果"再加载一次，没有位移动画。

**留存证据**：每台设备、每一步的截图或录屏，抓包导出的 HAR 文件，记下设备型号、系统版本、浏览器版本和测试时间，再写一份文字说明怎么重放这个场景。上面只要有一步没跑，就写"未验证"，不要写成"通过"。
